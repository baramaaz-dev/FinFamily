## 1. المشكلة

النص العربي المكتوب مباشرةً في ملفات SQL migrations يُخزَّن بترتيب أحرف معكوس
عند تحريره في بيئات LTR (محررات الكود على Windows · Supabase SQL editor).

**النتيجة:** "رأس مال" يُخزَّن كـ "لام سأر" في قاعدة البيانات.

**الحادثة المرجعية:** migration `20260612000001_fix_reversed_arabic_account_names.sql`
— أصلح 60 حساباً في قاعدة بيانات FinFamily بسبب هذه المشكلة.

## 2. القاعدة الإلزامية

**لا يُكتب نص عربي مباشر في أي ملف SQL.**

هذه القاعدة سارية على:
- ملفات `supabase/migrations/*.sql`
- دوال PostgreSQL (CREATE FUNCTION)
- Triggers
- Seed data
- أي استعلام SQL يحتوي قيم نصية عربية

## 3. البدائل المعتمدة

### البديل الأول — Unicode Escape Sequences ✅ (مُفضَّل)

كل حرف عربي يُكتب بصيغة `U&'\XXXX'` حيث XXXX هو كود Unicode للحرف.

مثال:
```
-- بدلاً من: 'رأس مال'
U&'\0631\0623\0633 \0645\0627\0644'
```

جدول الأحرف الأكثر استخداماً في FinFamily:

| الحرف | Unicode | الحرف | Unicode |
|-------|---------|-------|---------|
| ر | \0631 | م | \0645 |
| أ | \0623 | ا | \0627 |
| س | \0633 | ل | \0644 |
| مسحوبات (كاملة) | \0645\0633\062D\0648\0628\0627\062A | رأس مال (كاملة) | \0631\0623\0633 \0645\0627\0644 |

---

### البديل الثاني — الاشتقاق من البيانات الموجودة ✅

إذا كانت القيمة العربية المطلوبة موجودة بالفعل في جدول آخر،
يُشتق النص منه بدلاً من كتابته يدوياً.

مثال — بناء اسم حساب الشريك:

```sql
-- صحيح: الاسم مشتق من جدول people الذي أُدخل عبر واجهة RTL
UPDATE accounts a
SET name = U&'\0631\0623\0633 \0645\0627\0644 ' || p.name
FROM people p
WHERE a.metadata->>'partner_id' = p.id::text;

-- خطأ: كتابة الاسم العربي مباشرة
UPDATE accounts SET name = 'رأس مال السيدة الوالدة' WHERE code = '3130';
```

### البديل الثالث — بادئة إنجليزية للبيانات الداخلية ✅

للقيم التي لا يراها المستخدم (مفاتيح داخلية · reference codes · أنواع):

## 5. إجراء التحقق

قبل تطبيق أي migration يحتوي نصوصاً عربية، شغِّل هذا الاستعلام
للتأكد من صحة التخزين:

```sql
SELECT name, REVERSE(name) AS reversed
FROM accounts
WHERE name != REVERSE(name)
  AND name ~ '[\u0600-\u06FF]'
LIMIT 10;
```

إذا أعاد `REVERSE(name)` نصاً يبدو أصح من `name` → البيانات مخزَّنة معكوسة.

---

## 6. تطبيق القاعدة على Claude Code Prompts

كل Claude Code prompt يتضمن SQL بنصوص عربية يجب أن يحتوي التعليمات الآتية:

> **Arabic text rule:** Do NOT write Arabic string literals directly in SQL.
> Use Unicode escape sequences: U&'\XXXX' format.
> Example: U&'\0631\0623\0633 \0645\0627\0644' instead of 'رأس مال'
> Or derive Arabic strings from existing table data.
